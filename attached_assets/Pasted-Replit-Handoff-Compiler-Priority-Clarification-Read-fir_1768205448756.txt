Do not change MOLT hierarchy (Trigger → Directive → Instruction → Subject → Primary → Philosophy → Blueprint).

Do not change merge semantics (applyMerges is substitution per current behavior).
Changes must be small, deterministic, and fully traced.

Phase 2 — What we are changing (compiler)
Goal
Priority must be a pure tie-breaker:
Used only when two+ blocks collide within the same moltType
Never used to influence MOLT ordering
Never used to “promote” a Directive above a Primary, etc.
Required compiler changes (only if inspection finds violations)
Restrict priority sorting to same-molt contexts
In resolveAuthority.ts and composeActiveOrder.ts, ensure sorting is:
First grouped by moltType using canonical MOLT order
Then within each group, sort by priority (group/order/override) + id fallback
No global sort across mixed MOLT types.
Collision functions must be the only “winner selectors”
selectPrimary.ts must enforce exactly 1 per stack (as current v0 design).
For alternates bundles (intent=alternates) in Directive/Instruction/Subject/Blueprint:
winner chosen by priority (within same moltType by definition)
deterministic id fallback
trace event must include candidates + winner
Trace must explicitly state what priority means
In priority.ts trace events: language should indicate “peer tie-break” not “MOLT precedence.”
