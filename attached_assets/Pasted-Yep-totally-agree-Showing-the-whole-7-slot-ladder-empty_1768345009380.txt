Yep — totally agree. Showing the whole 7-slot ladder empty on first load is like opening a video game and immediately seeing the entire skill tree greyed out. It’s “informative,” but it’s not inviting.
The v0 tutorial should start like this:
One big CTA: “Create first block”
Then the graph appears (or “unfurls”) as the user creates roles.
What to change
Desired behavior
Fresh workspace (no blocks):
Graph shows a single “Start” node (or even a centered empty-state card)
Sidebar shows Create Block as the only primary action
No empty role cards on the graph
After first block is created:
Graph switches to showing the ladder, but only renders roles up to the highest created role
Optionally show the next missing role as a faint “ghost slot” (nice teaching)
After spine complete (all 7 created):
Graph shows full ladder
Extras are separate nodes or grouped under their role when expanded
Exact implementation (minimal, safe)
1) Update graph builder to not render role nodes when empty
In src/umg/graph/buildNodes.ts (or wherever you build the role ladder), add an early return:
Copy code
Ts
if (!blocks || blocks.length === 0) {
  return {
    nodes: [
      {
        id: "start",
        type: "startNode", // or reuse your basic node type
        position: { x: 0, y: 0 },
        data: {
          title: "Start",
          subtitle: "Create your first block to begin the MOLT spine.",
          cta: "Create Block",
        },
      },
    ],
    edges: [],
  };
}
If you don’t want a new node type, reuse your existing node type and just render different text.
2) Progressive ladder rendering (only show roles “unlocked”)
Compute highest spine index:
Copy code
Ts
const spine = getSpineBlocks(blocks);
const rolesPresent = new Set(spine.map(b => b.role));
const maxIndex = Math.max(
  -1,
  ...spine.map(b => MOLT_ORDER.indexOf(b.role))
);
Then only render roles up to maxIndex + 1 (so the next role appears as the next target):
Copy code
Ts
const rolesToRender = MOLT_ORDER.slice(0, Math.min(MOLT_ORDER.length, maxIndex + 2));
For each role:
if present → normal node
if missing but it’s the “next” → ghost/placeholder node
That keeps the graph from being cluttered at the start.
3) Make “Start node” clickable to create block
In your node component, if data.cta === "Create Block", on click call the store action:
Copy code
Ts
useUmgStore.getState().createBlock();
(or pass handlers in node data — cleaner, but this is v0-safe.)
4) Fit view on transition
When blocks go from 0 → 1, call fitView() once so the graph centers nicely. Don’t call it on every change.
