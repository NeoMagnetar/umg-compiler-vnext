The 4 most likely remaining issues (and how to fix them)
1) Tutorial step desync after refresh
Symptom: You have data, but tutorialStep is “EMPTY” or wrong.
Fix: derive tutorialStep from state on hydrate (or compute on the fly).
In store.ts after hydration, run:
If has 7 MOLT roles → at least READY_TO_COMPRESS
If neoBlocks.length > 0 → NEOBLOCK_CREATED
If neoBlocks.length >= 2 → DUPLICATED/READY_TO_COMPOSE etc.
If neoStacks exists → NEOSTACK_NAMED
If sleeve exists → SLEEVE_CREATED
If runtimeSpec exists → COMPILED
This makes persistence feel “real”.
2) Mobile page scroll fights ReactFlow pan
Symptom: You pan the graph and the whole page moves.
Fix: ensure the Graph tab container has:
height: 100%
touchAction: "none" on the ReactFlow wrapper
overflow: hidden
Example wrapper style:
Copy code
Ts
const graphWrap: React.CSSProperties = {
  height: "100%",
  width: "100%",
  overflow: "hidden",
  touchAction: "none",
};
3) Extra Blocks feature should not corrupt “spine”
Symptom: Extra blocks cause isMoltComplete to fail or mess up nextAllowedRole.
Fix rule: The “spine” is always the first block per role. Extras are stored separately or appended but ignored by isMoltComplete().
Implementation approach:
getSpineBlocksByRole() picks earliest created for each role
Extras are any additional blocks with same role
Compress snapshot uses spine only (or optionally spine + extras in future)
4) Merge/Bundle semantics still too “single-blocky”
Even with 7 roles, your merge/bundle is currently NeoBlock ↔ NeoBlock, which is correct.
But the “dominant snapshot” rule is simplistic (acceptable v0), so the UI must communicate that.
Fix: In Tutorial Output, explicitly say:
“v0 composition uses dominant snapshot (governancePriority slider decides which artifact wins).” That prevents user confusion.
